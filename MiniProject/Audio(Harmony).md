# Week 2 – Audio Acquisition and Playback

**ELIC329 – Real-Time Vocal Harmony Generator Using ESP32**

## 1. Introduction

This mini project develops the audio input and output foundation for a vocal harmony generator. The Week 2 objective is to capture sound using an I²S microphone, buffer the digital samples on an ESP32, and transfer the samples to a MAX98357A amplifier for live speaker playback.

The work documented here covers ESP32 programming setup, microphone wiring, buffered I²S acquisition, and sample visualization. Amplifier output and live microphone-to-speaker playback remain pending verification. Pitch shifting and harmony generation are later stages of the project.

## 3. System Design

### Target audio path

```mermaid
flowchart LR
    MIC["INMP441 microphone"] -->|"I²S data: GPIO33"| MCU["ESP32: capture and buffer"]
    MCU -->|"I²S data: GPIO22"| AMP["MAX98357A amplifier"]
    AMP -->|"SPK+ and SPK−"| SPK["Speaker"]
```

The ESP32 supplies BCLK on GPIO26 and WS on GPIO25. The target design shares these clocks between the microphone and amplifier. All modules share ground. The amplifier and speaker portion represents the planned playback path; it has not yet been demonstrated in the results below.

### I²S microphone connections — implemented

| INMP441 pin | ESP32 connection | Function |
|---|---|---|
| VDD | 3V3 | 3.3 V microphone supply |
| GND | GND | Ground reference |
| SCK / BCLK | GPIO26 / D26 | Bit clock generated by ESP32 |
| WS / LRCLK | GPIO25 / D25 | Audio frame and channel selection clock |
| SD / DOUT | GPIO33 / D33 | Microphone data to ESP32 |
| L/R | GND | Selects left-channel transmission |

The microphone header is soldered. L/R uses the ESP32 GND beside VIN, while the microphone GND uses the GND beside 3V3; these are common ground connections on the board.

### I²S amplifier connections — planned

| MAX98357A connection | Target connection |
|---|---|
| BCLK | ESP32 GPIO26 / D26 |
| LRC / WS | ESP32 GPIO25 / D25 |
| DIN | ESP32 GPIO22 / D22 |
| GND | Common ESP32 ground |
| VIN | Suitable supply verified against the specific amplifier breakout |
| SPK+ | Speaker positive terminal |
| SPK− | Speaker negative terminal |

The speaker connects across SPK+ and SPK−. Neither speaker output connects to GND. Supply and any SD/MODE or GAIN pin configuration must be confirmed for the actual breakout before the output test.

## 4. I²S Audio Input and Buffering

The microphone test uses a sampling rate of **16 kHz**. The INMP441 supplies signed 24-bit audio, received in **32-bit I²S slots**. Two slots are captured during diagnosis so that the active channel can be identified.

| Parameter | Diagnostic configuration |
|---|---|
| ESP32 role | I²S master and receiver |
| Sampling rate / WS frequency | 16,000 Hz |
| Slot width | 32 bits |
| Captured slots per frame | 2 |
| Target BCLK | 16,000 × 32 × 2 = 1.024 MHz |
| Frames per application buffer | 256 |
| Buffer allocation | 512 × 4 = 2,048 bytes |
| Duration represented by a full buffer | 256 / 16,000 = 16 ms |
| DMA configuration | 4 buffers, each configured for 256 frames |
| Serial baud rate | 115200 |

These clock values are calculated from the configuration; they were not measured with an oscilloscope.

The program continuously calls `i2s_read()` to transfer received samples into an `int32_t` array:

```cpp
int32_t audio[256 * 2];

size_t bytesRead = 0;
i2s_read(MIC_PORT, audio, sizeof(audio),
         &bytesRead, pdMS_TO_TICKS(1000));
```

Two adjacent array entries represent the two received channel slots. The diagnostic display labels them **A** and **B**, avoiding an assumption about software buffer ordering.

### Individual sample display

The final diagnostic approach displays individual samples rather than RMS values:

```cpp
float sampleA = audio[2 * i] / 65536.0f;
float sampleB = audio[2 * i + 1] / 65536.0f;

Serial.print("A:");
Serial.print(sampleA, 4);
Serial.print("\tB:");
Serial.println(sampleB, 4);
```

Division by 65536 scales the sample values for display. The displayed values are not volts or calibrated sound-pressure levels. Positive and negative values are normal because audio is represented as a signed waveform.

Serial output is limited to snapshots while the program continues receiving audio between display updates. Display interval and sample count were adjusted during testing; the exact settings used for the captured screenshot were not recorded.

## 5. Microphone Test and Observed Results

### Test procedure

1. Wire the INMP441 with USB power disconnected.
2. Select ESP32 Dev Module and the working ESP32 board package.
3. Upload the microphone acquisition sketch.
4. Open Serial Plotter at 115200 baud.
5. Observe both received slots and compare quiet input with speech or a clap.

The screenshot alone does not establish intelligibility, pitch accuracy, continuous waveform timing, or successful playback.

### Issues encountered and troubleshooting

| Issue | Action / outcome |
|---|---|
| Initial ESP32 core compilation and linking failures | Switching to ESP32 board package 2.0.17 produced a successful LED-test build and upload |
| Missing `driver/i2s.h` | Board selection and ESP32 package configuration were checked |
| Accidental punctuation and extra zeros in the sketch | The sketch was corrected before compiling again |
| Upload stopped at “Connecting…” | BOOT / reset procedure and serial-port selection were used as troubleshooting steps |
| Initial readings remained near zero | Power, wiring, soldered headers, channel selection, and raw data were investigated |
| A single-channel test did not reveal useful data | A two-slot diagnostic was introduced; the later plot shows activity in A |
| Readings scrolled too quickly | Serial display updates were limited independently of the 16 kHz acquisition rate |

## 6. I²S Output and Live Playback — Remaining Work

The next stage is to configure I²S transmission to the MAX98357A and send microphone samples to the speaker continuously.

The playback implementation must:

- Use matching 16 kHz input and output frame rates.
- Configure compatible I²S slot width and channel format.
- Select the valid microphone slot and map it to the amplifier output channels.
- Convert or scale sample values if the output format differs.
- Use buffered transfers / DMA and handle partial writes where necessary.
- Disable continuous Serial Plotter printing during playback.
- Keep the speaker separated from the microphone and begin at low volume to reduce feedback.

The Week 2 playback demonstration is complete only after speech captured by the microphone can be heard through the speaker. That result has not yet been supplied for this portfolio.
